## 更新方法

`scripts/build_public_site.py` は、親ディレクトリにある解析成果から `docs/` の公開物を再生成します。

```bash
python3 scripts/build_public_site.py
```

GitHub Pages は `main` への push 後に Actions から自動デプロイされます。

## 2026-10-30 最新版の統合と本文表示

- 環境：2026-10-28引用修正済み判定と2026-10-29の人手確認レイヤーを採用。2026-10-30に研究者が44件すべて確認済みと明示したため、「人手確認済み」として収録。判定内容・根拠・元のLLM判定を保持。
- エネルギー：2026-10-17の全5,094要求の統合結果と人手探索情報を採用。
- 要求クラスタリング：両計画の `要求クラスタリング/runs/final` を使用。再クラスタリングは行わない。
- 環境本文：最新判定の入力と同じ `追加修正_本文以降ID連番整理_全7版_20261028/tei` を使用。
- 議事録：両計画の `意見発言データ` の本ファイルを使用（` 2.xml` 等の複製は使わない）。
- 改訂判定に本文の右側表示・別タブ表示・ID指定の移動・引用ハイライトを追加。文書とIDに加え本文も全件照合。
- クラスタリングの散布図の点をクリックすると、議事録と該当要求の改訂判定を開ける。

環境の差分87要求は、すべて第116回部会「答申案の最終検討段階」の要求。
最新の保存済み判定に結果がないため、新しい判定を生成せず `not_evaluated`（未判定）で収録している。
環境は全2,298要求（判定済み2,211・未判定87）、エネルギーは全5,094要求。
単一文書の記載有無は改訂対応と区別する。人手確認44件の変更前の状態は `review_history` と
`backups/environment_before_review_confirmation_20261030.json.gz` に保存し、研究入力は変更しない。

変更前の公開データ・ビューア・生成スクリプト一式は `backups/site_before_20261030.zip` に保存。
研究入力・過去の解析結果は変更しない。公開版は再生成し、採用元ファイルのSHA256と照合件数を
`docs/data/publication_audit.json` に記録する。本文の引用は完全一致またはNFKC・空白正規化一致のみ強調し、
一致しない場合は対象段落のみを表示する。複数段落はすべてリンク対象に含める。

実装は `scripts/latest_site.py` と `scripts/web/`。同じビルドコマンドで再生成できる。

検証は `python3 scripts/verify_data.py` で全件のID・原データのハッシュ・公開物のチェックサム・バックアップを確認する。
`scripts/verify_site.mjs` はPlaywrightとChromeを使用し、`http://127.0.0.1:8765` に配信したサイトで
フィルタ、左右表示、別タブ、引用ハイライト、脚注・見出し・複数段落、スマートフォン幅、クラスタ点の導線を検証する。
別URLでの検証は `VIEWER_BASE_URL` で指定できる。
